Test labels and what a pass means

R = complete route · M = missing information · D = dates · F = follow-up · U = unsupported request · E = error / empty results · V = validation. These are our own case labels. R1 and R2 are different scenarios; the five dots are five repetitions of the same scenario.

A pass means the recorded behavior met the checks we wrote: search inputs, saved preferences, clarification, constraints and selected results. It does not certify real inventory accuracy, every displayed flight field, tone or WhatsApp formatting. All flights in these runs are simulated.

Five repeats are an initial consistency check, not a production accuracy guarantee. The clock is fixed at 18 September 2026. Cases and expected outcomes are written before execution. Each scenario starts fresh. Latency includes Codex startup, network and model generation; cached input is included in total input tokens. Results are development tests, not held-out tests. The complete model prompt includes Codex’s own instructions, so token counts are larger than the user message alone.

Scope: one-way, one traveler; business and today through seven days from today are defaults. Live inventory, checkout, round trip and multi-city are not connected. Test prices and routes are fabricated and may not correspond to real airline services.
